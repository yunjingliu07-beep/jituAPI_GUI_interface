# 更新日志与个人存储配额

## 更新日志

版本数据集中维护在 `worker/core.js` 导出的 `RELEASES` 中，最新版本放在数组首位。每次对用户发布更新时，新增一个不同的 `version`（例如 `2026.10.19.2`）、日期、标题和中文变更列表，再构建并部署。不要仅修改旧版本的内容，否则已读用户不会重新弹窗。重启同一个版本不会重复提示。

- 通过 `/api/updates` 返回更新列表，侧栏「更新日志」可随时查看。
- 登录用户关闭弹窗后，服务器记录 `users.last_seen_release`，同一账号在其他设备也不会重复自动弹出同一版本。
- 未登录访问使用浏览器 `image-meow-release-seen` 保存已读版本；清除浏览器数据后可能再次提示。匿名浏览器与登录账号分别判断阅读状态。
- 弹窗等当前对话框关闭后再出现，首次使用指引优先；关闭更新日志后才展示待确认的空间清理通知。
- 阅读状态同步失败时不会在当前页面反复弹窗，下次打开时会再次提醒。

## 账号存储配额

默认容量为 **3,000,000,000 字节（3 GB）**，实际上限由 `account_storage.limit_bytes` 保存，浏览器传入的用户 ID、容量参数不能改变配额。账号页展示用量和进度条。

计量包含已提交参考图、遮罩及生成图片的原始文件大小，以及对话与任务文字的 UTF-8 字节数。每条任务额外计 4096 字节、每个会话计 512 字节，用于其他元数据与记录开销。这是用户数据配额；共享 SQLite 页、索引、WAL、账号及 API 配置等不能精确拆分到每个账号，不在该用量中。SQLite 删除释放的页会供数据库后续复用，数据库文件不一定立即缩小。生成结果保存到本站后按文件大小和清单字节计入配额；尚未保存的供应商结果不计入本站文件用量。已登记但写入未完成的结果也会占用预留空间，直到保存或清理完成。

- 新增任务、参考图和会话元数据写入前，先计算本次提交增长量；刚好达到上限不会触发删除。
- 不足时按**会话创建时间**从旧到新移除整个会话及其任务、生成图片、参考图和遮罩。置顶不豁免，最近修改时间不改变清理顺序。
- 当前提交的会话及 20 分钟内仍处于提交中、待核对、排队或生成中的会话暂不自动删除。没有可清理数据时返回空间不足，不调用付费生图接口。当前会话自身过大时提示新建会话。
- 账户密码、登录会话和 API 配置保留。
- 启动服务时会检查现有账号，处理已超额的历史数据；访问个人空间或写入记录时也会核算。
- 同一账号的空间写入使用数据库租约互斥，多个页面/进程不能同时绕过配额；网络生图调用不会长时间占用此锁。

## 文件失败恢复与通知

上传前先记录完整文件清单。若上传或删除中断，文件清单会保留，未完成的数据继续计入用量，避免产生不受配额管理的孤立文件。恢复提交会重新保存未完成的参考图；未完成的图片不会对外提供下载。

清理会先将会话隐藏，并在同一事务中记录账号清理通知，再删除文件。物理删除成功后才删除任务清单；失败时下次检查继续重试，暂停新增数据以免继续占用磁盘。文件删除还会移除已空的任务目录。最小会话墓碑保留，用于阻止旧页面恢复已删除的会话。

空间清理通知保存于 `account_storage`，刷新、退出登录或重启不会丢失。用户会看到清理会话数和任务数，并可确认通知；旧页面确认旧通知不会吞掉后来发生的新清理。前端会重新同步历史列表，移除已清理内容。

用户应在账号页和本次更新日志中看到清理规则；清理后无法从本站恢复已删除数据。

## Ubuntu 部署

本次新增迁移 `0004_updates_storage.sql`，必须先迁移，再启动新代码。建议先按现有流程备份数据库、原图和 `/etc/image-meow/server.env`。更新代码后，使用现有安装器完成停服迁移和启动：

```bash
cd /opt/image-meow
sudo git pull --ff-only origin main
sudo bash deploy/ubuntu/install.sh imagemeow.top
```

安装器保留现有配置和 HTTPS 配置。不要重新生成 `API_VAULT_KEY`。启动时将按上述规则清理已经超额的旧会话；其他账号与未超额的数据保留。

检查：

```bash
systemctl is-active image-meow
curl --fail --silent --show-error https://imagemeow.top/api/updates
```

然后登录网站：应能看到更新弹窗、侧栏更新日志入口、账号页的容量信息。关闭更新弹窗后刷新，不应重复提示；清理通知在确认前保持可见。匿名 `curl` 不能访问 `/api/storage`，须通过登录后的浏览器验证。

## 验证范围

自动测试覆盖精确边界、新任务预留空间、最早会话顺序、置顶会话、跨账号隔离、旧格式记录、生成中会话保护、并发租约、部分上传与物理删除失败后的恢复、启动时处理现有超额用户、通知确认竞争、更新已读状态及重启持久性。容量测试用已登记的文件大小模拟大文件，避免测试过程中实际写入 GB 级数据。生图调用使用模拟供应商，不产生真实费用。


## 2026-10-26 更新部署

本次新增 `0007_account_storage_limit.sql`，为账号保存独立容量，并在迁移时应用本次指定的账户配额。前端容量、空间不足判断和启动清理使用同一配额。容量调整不进入用户更新日志。

生图任务从 `created_at` 起计时，20 分钟后把仍处于提交中、待核对、排队或生成中的任务持久保存为 `timed_out`，保留提示词、参数和参考图。启动时检查全站旧任务，运行期间每秒检查；请求处理及前端也会检查。超时任务不会再次查询或恢复原提交；迟到的响应不能将其改回进行中。重新生图需要用户再次发送，使用新的提交标记。

生产站需手动执行以下命令（更新脚本会停服、备份、迁移并重启；不要只重启服务）：

```bash
cd /opt/image-meow &&
sudo git pull --ff-only origin main &&
sudo bash deploy/ubuntu/update.sh
```

启动后已有超时任务会自动结束；账户页会按实际配额显示容量。Sites 镜像继续保持迁移暂停状态，发布镜像不会更新 Ubuntu 上的数据或服务。


## 生成图片持久保存（2026.10.26.2）

新增迁移 `0008_generated_results.sql`，保存结果文件清单、实际张数、保存状态和保存错误。生成成功后立即获取原图并保存；Ubuntu 默认写入 `/var/lib/image-meow/generated/<用户 ID>/<任务 ID>/<序号>`，文件类型保存在清单中。Sites 使用原 `BUCKET` 的 `generated/` 前缀，仍保留迁移暂停状态。

- 查询成功结果和立即返回图片的提交都会触发保存。后台每 5 秒检查最多 10 个任务，只查询原任务，绝不提交新的生图。后台使用该账户已保存的原 API 配置或匹配密钥摘要的配置；旧任务没有已保存密钥时，需用户连接原 API 打开会话，才能补存。
- 后台会尝试补存仍在供应商 12 小时有效期内、且具备原 API 的历史成功任务。超过有效期且此前未保存的图片无法凭聊天记录补回；不会自动重新生图。
- 已保存的图片按账户鉴权读取，不需要 API 密钥；刷新、跨设备和服务重启后仍可查看。已保存部分不再受 12 小时有效期限制，但仍遵循空间清理和会话删除规则。
- 多张结果逐张保存，页面显示实际已保存张数。磁盘、下载或容量不足时保留成功部分、任务记录和错误提示，可「重试保存」；未保存部分仍需及时下载。当前会话自身已满时不会删除该会话来保存结果。
- 文件写入前在账户租约内预留容量并登记清单，完成后才标记可读。重复查询不会重复保存或重复计量；失败的预留和文件清单保留，可重试覆盖同一目标或随会话清理。删除失败时先隐藏会话，待物理删除完成才删除清单。
- 备份脚本已备份整个 `/var/lib/image-meow`，新增结果目录随之包含在备份中。

在 Ubuntu 执行以下命令后，数据库迁移和新功能才会生效：

```bash
cd /opt/image-meow &&
sudo git pull --ff-only origin main &&
sudo bash deploy/ubuntu/update.sh
```

无需修改目录所有者、另配磁盘路径或单独重启服务。


## 全站配额提升至 3 GB（2026-10-31）

新增迁移 `0009_storage_quota_3gb.sql`，为没有配额记录的现有账号创建 3 GB 配额，仅将低于 3,000,000,000 字节的记录提升至该值。已有 3 GB 或更大配额（包括原 5 GB 账号）保持不变；清理通知、租约和文件数据保留。新账号创建配额记录时明确写入 3 GB，未创建记录时也按 3 GB 计算。既有迁移文件保持不变。

Ubuntu 使用 `app_data_migrations` 记录这次数据迁移，成功后不会在重启或再次更新时重复应用；迁移在启动容量清理之前完成。本次全站容量更新会显示在用户更新日志中。Sites 镜像继续保持暂停。

在正式服务器执行（脚本会停服、备份、迁移并启动，不能只重启服务）：

```bash
cd /opt/image-meow && sudo git pull --ff-only origin main && sudo bash deploy/ubuntu/update.sh
```

更新完成后登录账号页查看容量；原有高配额账号应继续显示原容量。
