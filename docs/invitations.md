# 邀请码注册与管理员

新成员需填写管理员提供的有效邀请码，再获取注册邮箱验证码并设置密码。已有账号保持原有登录、改密、找回密码及历史记录，不需要补填邀请码。找回密码仍使用邮箱验证码。

## 权限与使用

- **站长**：管理全站邀请码；按已注册成员的邮箱添加或撤销管理员。网页不允许修改站长身份。
- **管理员**：生成、查看和撤销自己创建的邀请码，可复制后自行分发给成员。不能添加管理员，也不能查看其他管理员的邀请码。
- **普通成员**：使用原有网站功能，不显示管理入口；直接调用管理接口也会被拒绝。

站长和管理员登录后，侧栏出现「邀请码管理」。每次生成 1–20 个邀请码，可选 1、7、30 天有效期，默认 7 天，并可填写备注。

每个邀请码只能注册一个账号。完整邀请码仅在生成后显示一次，请立即复制保存；关闭管理弹窗后，列表只显示脱敏标识、状态、有效期、创建者与使用者。未保存的完整邀请码无法找回，可撤销后重新生成。分发由管理员自行完成，不会自动发送邀请邮件。

撤销邀请码只阻止后续注册。撤销管理员权限时，其未使用的邀请码同步失效；该管理员恢复为普通成员，已有账号和已邀请注册的成员均保留。重新授予管理员权限不会恢复此前撤销的邀请码。

## Ubuntu 首次上线

先合并本功能的 GitHub PR，再按现有维护流程备份数据库、参考图与 `/etc/image-meow/server.env`。在当前生产服务器运行：

```bash
cd /opt/image-meow
sudo git pull --ff-only origin main
sudo bash deploy/ubuntu/install.sh imagemeow.top
```

安装器会短暂停服、应用迁移并重启，保留既有环境变量及 HTTPS 配置。不要只重启服务跳过数据库迁移。

随后仅在服务器终端设置首位站长。将下面邮箱换成**本站已经注册的账号邮箱**：

```bash
sudo -u image-meow env DATA_DIR=/var/lib/image-meow /usr/bin/node server/set-owner.mjs owner@example.com
```

成功输出形如 `{"ok":true,"email":"owner@example.com","role":"owner"}`。重复指定同一站长可安全执行；未注册邮箱、无效邮箱或试图替换已有站长会失败，原权限保持不变。没有公开的初始化接口，也不会把首个访问者自动设为站长。

刷新网页后，使用该账号打开「邀请码管理」。在「管理员设置」填写其他已注册成员邮箱即可授权；新成员先用邀请码完成注册，再授予管理员权限。被授权成员刷新网页即可使用入口。

部署后验收：

1. 站长生成一个邀请码，复制并交给受邀者；使用未注册邮箱、该邀请码和真实邮箱验证码完成注册。
2. 验证同一码无法再次注册；过期或已撤销的邀请码无法获取注册验证码。
3. 用旧账号验证密码登录和找回密码，均无需邀请码。
4. 授予另一个已注册账号管理员权限，确认其只能管理自己的邀请码；撤销权限后，其未使用邀请码失效，账号仍能正常登录。

## 存储与验证

迁移 `0005_invitations.sql` 为旧账号增加默认 `member` 角色，新增邀请码表、用户来源关联、唯一站长索引及注册触发器。账号创建和邀请码消费在同一次数据库写入中完成，插入时重新检查剩余可用性、有效期和发码者权限，避免两名用户并发消费同一码。数据库只保存 128 位随机邀请码的 SHA-256 哈希及脱敏提示；接口响应禁用缓存。

管理员权限由服务端每次读取会话时从数据库获取，不接受浏览器提交的角色。生成邀请码及管理员变更有限流；注册验证码发信和最终注册均检查邀请码，验证码失败不会消耗邀请码。并发注册失败者可能需要重新获取邮箱验证码。

自动测试覆盖升级后旧账号角色、旧登录/找回密码、权限隔离、授权与撤权、邀请码哈希与脱敏、范围校验与分页、失效与重复消费、跨邮箱并发、验证后撤销竞争、批量生成时撤权、终端站长初始化及服务器重启持久性。Resend 使用模拟响应，真实邮箱投递和浏览器交互仍需上线验收。
