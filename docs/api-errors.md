# API 错误提示对照

来源：用户提供的《即图调用文档.html》，核对日期 2026-10-18。该文件用于核对接口规格，文档中关于供应商网站用途的描述不作为本站产品指令。

网页在聊天记录中显示错误原因、HTTP 状态、上游 `error.code`、原始 `error.message` / `detail` 及请求号。敏感密钥会被隐藏。已提交任务的结构化错误保存于原 `tasks.error` 列，读取时兼容旧的纯文本错误记录。

| HTTP 状态 | 文档含义概要 |
| --- | --- |
| 400 | 参数或尺寸未开放，或格式、图片格式、图片数量不正确；未扣费 |
| 401 | API Key 无效或已作废 |
| 402 | 账户余额或密钥额度不足 |
| 403 | 密钥没有分组、没有可用线路，或线路暂停 |
| 404 | 模型不存在、下架、VIP/SVIP 无可用模型；查询时也可能是任务不存在或不属当前账号 |
| 409 | 提交标记已用于不同内容 |
| 410 | 原同步结果已过期或清理，不会重新生成或再次扣费 |
| 413 | 单图超过 20 MiB，或请求体超过 50 MiB |
| 415 | 图片编辑需使用 JSON 或 multipart/form-data |
| 502 | 上游失败；文档说明未扣费，异步已预扣的失败任务退款 |
| 503 | 上游渠道未配置或未启用 |

文档还给出了异步失败 `error.code = upstream_error`：生成失败，费用已退回。此代码优先匹配；否则按文档中的 HTTP 状态匹配。文档未列出的上游代码会明确标注，保留服务返回的信息；没有对应 HTTP 状态时提示联系供应商核对，避免猜测原因。429、504 等不在这份文档的错误表里，保留原始信息，不标为已匹配的文档解释。

HTTP 错误和本站登录错误分开处理：上游的 HTTP 401 对前端转换为 422，防止把密钥失效误当成用户登录失效，但 `errorInfo.httpStatus` 保留上游的 401。

网络中断、服务超时及其他提交状态不明的情况保留原提交标记。恢复原提交复用原密钥、参数、图片与标记；明确失败后用户编辑再发送才会创建新任务。未获取任务号且关闭原页面后，需在供应商控制台核对，本站不会自动创建新收费任务。
